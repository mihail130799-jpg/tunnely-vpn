## Что сделано
- **Ядро:** `vpn_core/tunnelycore` — Go-обёртка **Xray-core v26.10.21** (StartWithFd/Stop/Validate/TrafficNow/DelayError/RecentLogs/RecentEvents/AppendEvent/ClearLogs, Protector). AAR через gomobile (`scripts/build_core_android.*`, `-checklinkname=0`). См. ADR 0003.
- **Dart (`vpn_client/lib`):**
  - разбор ссылок vless/trojan/ss/vmess/hysteria2/tuic и подписок (base64, список, Clash YAML, заголовки панели);
  - генератор конфига Xray (`core/xray_config.dart`): TUN, DNS (Яндекс DoH для РФ напрямую, Cloudflare/Google через VPN), «Авто» = leastPing + observatory, маршрутизация «РФ напрямую» (домены + 8 672 IPv4-диапазона), probe-конфиг для проверок без туннеля;
  - контроллер: импорт, дубликаты, подписки (раз в сутки), проверка серверов настоящим запросом через ядро с причиной сбоя, распознавание истёкшей подписки, «Авто» стартует на самом быстром живом сервере, отчёт диагностики;
  - журнал приложения (`services/app_log.dart`) и экран «Журнал работы» (приложение / VPN-служба / ядро, подробный режим ядра).
- **Android:** VpnService + foreground-уведомление, смена сети, Keystore-шифрование конфига, плитка, виджет, deep links, события службы в журнал.
- **UI:** концепция C, обе темы, виджет 3×1.
- **Сборка/CI:** `setup_windows.ps1`, `test_project.ps1`, `build_android.ps1`, `build_core_android.{ps1,sh}`, GitHub Actions `android.yml`.

## Известные проблемы и непроверенное
- 0.1.x (Mihomo) на телефоне владельца: «Ни один сервер не отвечает» при рабочем Happ. Причина — несовместимость Mihomo с новыми Xray-серверами (ADR 0003). Исправлено переходом на Xray в 0.2.0; на реальном телефоне в России ещё не подтверждено.
- Тестовые подписки владельца отзываются (старая — 404); число в токене ссылки — время создания, не срок действия. Текущая — только в `secrets/test_subscription.txt`.
- Hysteria2, TUIC, SS-плагины, h2 не поддерживаются Xray-ядром приложения (у владельца только VLESS).
- Не проверены: QR-сканер (нет камеры в эмуляторе), Trojan/SS/VMess/XHTTP на живых серверах, долгая работа в фоне на прошивках с агрессивной экономией батареи.
- GitHub Actions ещё не запускался после публикации — проверить первый прогон.
