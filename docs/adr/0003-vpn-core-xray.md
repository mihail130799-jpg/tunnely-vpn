# ADR 0003: ядро — Xray-core (заменяет ADR 0002 «Mihomo»)

Дата: 2026-10-28. Статус: **принято владельцем**.

## Что случилось
Версия 0.1.1 (ядро Mihomo) на телефоне владельца в России показывала «Ни один сервер не отвечает», хотя Happ (ядро Xray) с той же подпиской на том же телефоне работал.

## Причины
- Серверы владельца — свежий **Xray** с Reality + Vision + **VLESS Encryption** (`mlkem768x25519plus`) и отпечатком `firefox`. Reality, Vision, VLESS Encryption и XHTTP — технологии Xray, его реализация эталонная.
- Новые REALITY-серверы требуют ключ X25519MLKEM768; Mihomo его по умолчанию не шлёт, а шаблон `firefox` в Mihomo не умеет. В 0.1.0–0.1.1 это обходилось заменой отпечатка на `chrome` — то есть приложение подключалось не так, как задано в ключе владельца и как подключается Happ.
- Разработчики Mihomo отказались подстраиваться под новые Xray-серверы (issue #3339, NOT_PLANNED) и намеренно сообщают серверу устаревшую версию клиента (1.8.2).
- В России фильтрация (ТСПУ) реагирует на сетевой «почерк» клиента, поэтому отклонение от заданного в ключе отпечатка — реальный риск.

## Решение
Ядро — **Xray-core v26.10.21** (то же, что у Happ), встроенное через gomobile (`vpn_core/tunnelycore`):
- TUN — встроенный inbound `tun` Xray; Android-дескриптор передаётся через флаг `xray.tun.fd`.
- Конфиг — JSON Xray, генерируется на Dart (`lib/core/xray_config.dart`) из тех же разобранных ссылок/подписок.
- «Авто» — балансировщик `leastPing` + `observatory`; перед подключением приложение само проверяет все серверы и стартует на самом быстром живом (`fallbackTag`).
- Проверка серверов — настоящий HTTP-запрос через конкретный outbound (`session.SetForcedOutboundTagToContext`), в том числе до подключения (временное ядро без TUN).
- DNS — модуль DNS Xray: Яндекс DoH напрямую для российских доменов, Cloudflare/Google DoH через туннель.
- Маршрутизация «РФ напрямую» — список доменов + 8 672 российских IPv4-диапазона (ipverse/rir-ip, CC0) прямо в конфиге.
- Скорость — по счётчикам outbound (счётчики TUN-inbound занижают значения).
- Сборка: `-ldflags=-checklinkname=0` (как в v2rayNG/libXray), Go 1.27.

## Проверено (2026-10-28)
- Серверы владельца Frankfurt и Finland через Xray с отпечатком `firefox` из ключа — ответ получен (с этого ПК).
- На эмуляторе: «Авто» выбирает живой сервер среди мёртвых (старая подписка), трафик и DNS через туннель, смена Wi-Fi ↔ мобильная сеть, скорость.
- **На телефоне владельца в России (28.10.2026): работает — YouTube и Telegram грузятся.**

## Последствия
- Протоколы Hysteria2 и TUIC в Xray не поддерживаются этим приложением (помечаются «не поддерживается»); у владельца только VLESS.
- Лицензии: Xray-core — MPL-2.0. Код Tunnely остаётся под GPL-3.0 (решение владельца №9; MPL-2.0 совместима с GPL). Можно сменить лицензию отдельным решением.
- APK стал меньше: ~25 МБ вместо ~37 МБ.
